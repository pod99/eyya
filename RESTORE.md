# Перенос EYYA

## Статус

Исходники скопированы с рабочего VPS 195.133.52.171. Публичная версия содержит заглушки вместо обнаруженных рабочих секретов. Полная резервная копия готовится отдельно; её наличие и целостность нужно подтвердить до отключения старого VPS. Восстановление на новом VPS пока не проверено.

## Содержимое

- `server/opt`: n8n (файлы запуска), EYYA dashboard, CloudKassir, Bitrix export / Trino, Tilda–Bitrix, Telegram / GreenAPI, FF bots.
- Отдельный приватный архив: оригинальные исходники, `.env`, сертификаты, ключи, базы, почта, Docker volumes и Docker images, конфигурация системы.
- Приватная инвентаризация описывает контейнеры, тома, монтирования, cron и systemd. Она содержит секреты и не публикуется здесь.

n8n workflows и credentials находятся в базе n8n и требуют исходного ключа шифрования. Почта Mailcow требует совместного переноса томов mysql, vmail, crypt, redis и конфигурации.

## Порядок восстановления

1. Проверить SHA256 скачанного приватного архива по контрольной сумме с исходного VPS.
2. Подготовить Ubuntu 24.04 и совместимую версию Docker; ограничить права на приватные файлы.
3. Распаковать архив в отдельный каталог, не поверх работающей ОС. Сохранить владельцев, права, ACL и extended attributes.
4. Перенести нужные `/opt` проекты, bind mounts, Docker volumes, сертификаты и секреты. Восстанавливать базы из логических SQL дампов либо из согласованной холодной копии с совместимой версией СУБД.
5. При переносе всего `/var/lib/docker` остановить Docker и containerd; использовать совместимую версию Docker и storage driver. Архив содержит локальные образы, включая собственные сборки.
6. Адаптировать nginx, UFW, Mailcow bind addresses, DNS A/AAAA/SPF и PTR к новому серверу. Не копировать старые настройки сетевого интерфейса вслепую.
7. Восстановить systemd units, cron и timers по приватной инвентаризации. Сначала запускать приложения без производственных cron, webhook consumers и workers, чтобы два сервера не обрабатывали одни события одновременно.
8. Проверить n8n workflow/credentials, dashboard login, БД, Mailcow IMAP/SMTP/webmail, приём и отправку писем, TLS, DKIM и интеграции. Переключить внешние webhooks и DNS после проверки.
9. Отключить обработчики на старом сервере при переключении. Сохранять старый VPS и проверенную резервную копию до успешного переноса.

Публичные файлы с `REPLACE_WITH_PRIVATE_*` предназначены для просмотра кода. Рабочие значения брать из приватной резервной копии, а не из этого репозитория.
